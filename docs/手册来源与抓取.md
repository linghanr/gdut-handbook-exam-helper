# 手册来源与一键抓取

## 一、来源

两份手册的原件由学校 OA（`oas.gdut.edu.cn`）公示页发布：

```
https://oas.gdut.edu.cn/seeyon/newsData.do?method=newsView&newsId=4414529617552949729
```

该页共有 4 个附件：

| 附件 | 内容 | 大小 | fileId |
| --- | --- | --- | --- |
| 附件1 | 2026级本科生、研究生入学教育网络考学操作指南 | 1,496,270 B | 6357886511145174938 |
| 附件2 | 各学院课群邀请码 | 129,777 B | -9144402948797479421 |
| **附件3** | **广东工业大学2026年学生手册（本科生手册）** | **3,937,067 B** | **4531777268578995019** |
| **附件4** | **广东工业大学2026年研究生手册** | **1,467,353 B** | **490323789424183750** |

> 仓库不包含这两个 PDF（版权归学校）。`src/fetch_handbooks.js` 会自动识别附件3 / 附件4 并保存为 `manuals/本科学生手册.pdf`、`manuals/2026研究生手册.pdf`，再转换为带页码锚点的纯文本 `data/handbook/*.txt`。

## 二、附件下载机制（逆向记录）

### 附件列表藏在页面属性里

OA 用 Seeyon CMS，附件清单以 JSON 形式内联在页面 DOM 元素的 `attsdata='[...]'` 属性中。字段包括 `id`、`fileUrl`、`filename`、`v`、`size`、`createdate` 等。

解析时的坑：

- **页面正文是 GBK/GB2312 编码，而 `attsdata` 里的 JSON 是 UTF-8**。直接整页按 UTF-8 解码会把正文变成乱码，但 JSON 部分仍然正确。稳妥做法是**按字节读取**，先在字节层面定位 `attsdata='` 与配对的 `]`，再只对这一段按 UTF-8 解码。
- JSON 内部可能出现 `]`，所以要**按括号深度**扫描结束位置，不能用 `\[.*?\]` 贪婪/惰性匹配。

### 直链格式

```
https://oas.gdut.edu.cn/seeyon/fileDownload.do
    ?method=doDownload
    &filename=<URL 编码后的附件名>
    &v=<版本串>
    &fileId=<fileUrl>
    &createDate=<yyyy-MM-dd>
```

Seeyon 前端 `downloadAttachmentNew` / `newHrefStr` 生成的正是这个模板（另有一个 `method=download` 变体）。

### 三个关键结论

1. **`v` 与会话绑定**：同一个附件，每次重新打开页面拿到的 `v` 都不同（游客会话与登录会话的值也不同）。因此必须"**同一会话取页 + 同一会话下载**"，不能把 A 会话的直链拿到 B 会话里用。
2. **游客无法下载**：无 Cookie 时接口返回"被迫下线，与服务器失去连接"的 HTML 页面（HTTP 200 但不是 PDF）；REST 端点 `/rest/attachment/file/batchDownload/...` 返回 `401 {"code":401,"success":false,"message":"该资源不允许Guest访问…"}`。**必须带 OA 登录态**。
3. **不能用"看起来对"的路径**：以下路径实测均不可用，不要再尝试 ——

   - `/seeyon/attachmentDownload.do?fileUrl=<id>&fType=1` → 404 或登录页
   - `/seeyon/fileDownload?fileUrl=<id>` → 404（缺少 `.do`）
   - `/seeyon/v3x/file/download` → 404
   - `/seeyon/officeTrans.do?method=view` → 404
   - `/rest/attachment/file/download/<id>`、`/rest/attachment/download` → 401

## 三、两种取件方式

### 方式 A：浏览器模式（推荐）

OA 需要登录，手动把 Cookie 复制出来容易出错。浏览器模式直接借用**已登录的调试 Chrome**：

```bash
node src/start_chrome.js "https://oas.gdut.edu.cn/seeyon/newsData.do?method=newsView&newsId=4414529617552949729"
# 在弹出的窗口里完成 OA 登录
node src/fetch_handbooks.js
```

脚本流程：在页面上下文用 `fetch(url, {credentials:'include'})` 重新取一次 OA 页面 → 解析 `attsdata` → 拼直链 → 同会话下载 → 转 base64 分片（1 MB/片）回传给 Node 端落盘。

### 方式 B：Cookie 模式

```bash
node src/fetch_handbooks.js --cookie "JSESSIONID=xxx; route=yyy; ..."
```

在浏览器开发者工具 → Network → 任意请求 → Request Headers → Cookie，整段复制即可。

### 只看清单（无需登录）

```bash
node src/fetch_handbooks.js --list
```

会输出 4 个附件的名称、字节数、fileId 与直链模板。

## 四、产物与校验

- `manuals/本科学生手册.pdf`、`manuals/2026研究生手册.pdf`：原件
- `data/handbook/本科学生手册.txt`、`data/handbook/2026研究生手册.txt`：纯文本，每页以 `===== [PAGE n] =====` 开头，`find_in_handbook.js` 依赖这个锚点输出页码

下载后脚本会做两项校验：

1. 文件头必须是 `%PDF-`（否则报"未取到 PDF，多半是未登录或会话已过期"）；
2. 字节数应与 `attsdata` 里声明的 `size` 一致，不一致会给出警告。

### 实测校验结果

在已登录 OA 的调试 Chrome 中跑通浏览器模式后，与此前手工取得的原件逐字节比对：

| 文件 | 字节数 | MD5（前 12 位） | 与手工原件 |
| --- | --- | --- | --- |
| `manuals/本科学生手册.pdf` | 3,937,067 | `ce1f4e66337c` | 完全一致 |
| `manuals/2026研究生手册.pdf` | 1,467,353 | `287a800a8fab` | 完全一致 |

转换出的纯文本（172,267 / 198,912 字）与此前手工抽取的版本**逐字相同**，页码锚点也一致，
因此 `find_in_handbook.js` 输出的页码可直接引用到答案出处。

## 五、文本抽取

```bash
python src/extract_pdf.py manuals/本科学生手册.pdf data/handbook/本科学生手册.txt
```

依赖 `pymupdf`（见 `requirements.txt`）。脚本兼容 `import fitz` 与 `import pymupdf` 两种写法。

若 `pymupdf` 装在非默认解释器里，用环境变量指定：

```bash
PYTHON=/path/to/python node src/fetch_handbooks.js
```
