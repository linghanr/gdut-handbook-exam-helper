# 使用指南

面向同学的一步步操作说明。全流程约 10 分钟。

---

## 0. 环境准备

| 依赖 | 版本要求 | 用途 |
| --- | --- | --- |
| Node.js | 18 及以上（需内置全局 `WebSocket`） | 运行全部 JS 脚本 |
| Python | 3.8 及以上 | 仅在需要重新解析手册 PDF 时使用 |
| Chrome | 任意较新版本 | 带调试端口运行 |

```bash
node -v      # 应输出 v18 以上
python --version
```

Python 依赖（可选）：

```bash
pip install -r requirements.txt
```

---

## 1. 启动带调试端口的 Chrome

```bash
node src/start_chrome.js
```

脚本会：

1. 自动定位 Chrome 可执行文件（Windows / macOS / Linux 常见路径）；
2. 用**独立用户目录** `~/.gdut-exam-chrome` 启动，不污染你日常浏览器的配置；
3. 打开考试平台首页。

> 手动等价命令：
> ```bash
> chrome --remote-debugging-port=9222 --user-data-dir=~/.gdut-exam-chrome
> ```

确认调试端口可用：

```bash
curl http://127.0.0.1:9222/json/list
```

能返回 JSON 列表即表示成功。

---

## 2. 登录并打开考试页面

在刚才启动的 Chrome 窗口里：

1. 登录考试平台账号；
2. 进入「在线考试」，打开正在进行的考试（地址形如 `.../exam/<id>/take`）。

**保持这个页面开着**，后续脚本都会驱动它。

---

## 3. 抓取试卷与题面

```bash
node src/fetch_paper.js
node src/dump_questions.js
```

- `fetch_paper.js` 会读取页面自己发出的接口请求，**自动复用其中的 token / userId / examId**，无需手工抄参数；
- 产物：`data/paper.json`（原始数据）、`data/questions.txt`（人可读题面）。`data/paper.json` 含本次考试的运行时信息，已在 `.gitignore` 中排除，请勿提交到公开仓库。

如果抓到的题量或题面与 `data/answers.json` 里的 100 题不一致，请以自己抓到的版本为准，重新汇总答案时按新题面调整。

---

## 4. 自动作答

```bash
# 全量（第 1~100 题）
node src/run_exam.js

# 只做一段（例如第 50~70 题）
node src/run_exam.js --from 50 --to 70

# 自定义批次大小（默认 25）
node src/run_exam.js --batch 10
```

脚本行为：

1. 按**选项文本**在页面上找到目标选项并点击（试卷选项显示顺序被打乱，**不能按下标**）；
2. 已选中的选项不会重复点击（避免被取消）；
3. 点「下一题」翻页，必要时自动回退「上一题」定位；
4. 逐题输出 `✓ 题号 [ok]` 的执行结果，`✗` 表示该题有问题。

> 脚本**不会**点击「交卷」，任何情况下都只停在考试页。
>
> 作答期间会临时安装一个「交卷/提交」点击拦截器，防止任何误触；
> 作答结束自动解除，**你自己点「交卷」提交仍然正常**。
>
> 最后一题不会再点「下一题」——平台在最后一题点「下一题」会弹出「确认交卷」对话框，这是最容易误交卷的地方。

---

## 5. 核验与收尾

```bash
node src/verify_final.js   # 逐题比对页面缓存与答案文件
node src/goto_last.js      # 跳到最后一题
```

`verify_final.js` 输出的 `核验通过 100/100 题` 表示页面上的作答与 `data/answers.json` 完全一致；
报告会写入 `data/verify_report.json`，不一致的题目会逐条列出。

---

## 6. 抓取并检索手册原文

仓库不包含手册 PDF 与纯文本（版权归学校），先一键抓取：

```bash
# 方式 A：浏览器模式 —— 先用 start_chrome.js 打开 OA 页面并登录，再执行
node src/start_chrome.js "https://oas.gdut.edu.cn/seeyon/newsData.do?method=newsView&newsId=4414529617552949729"
node src/fetch_handbooks.js

# 方式 B：Cookie 模式
node src/fetch_handbooks.js --cookie "JSESSIONID=...; ..."
```

产物：`manuals/*.pdf`（原件）与 `data/handbook/*.txt`（带页码锚点的纯文本）。
机制细节见 [手册来源与抓取](手册来源与抓取.md)。

然后检索：

```bash
node src/find_in_handbook.js "外借期限"
node src/find_in_handbook.js "留校察看" 8
```

输出形如：

```
[本科学生手册.txt p279] （三）外借期限：校内读者60天；校外读者30天
```

若要手工重新抽取带页码的纯文本：

```bash
python src/extract_pdf.py manuals/本科学生手册.pdf data/handbook/本科学生手册.txt
```

## 7. 维护自己的答案

答案条目统一为 `{q, answer, quote, src}`：

```json
{
  "q": 1,
  "answer": "B",
  "quote": "为赌博提供条件或者参与赌博的，视情节轻重给予记过以上处分",
  "src": "手册A p133 / 手册B p140"
}
```

多选题的 `answer` 用数组：`["A","B","C","D"]`。

把新条目放进 `data/answers_src/*.json`，然后：

```bash
node src/build_answers.js
```

会自动重新生成 `data/answers.json` 与 `docs/答案速查表.md`；若同一题在多个文件中给出不同答案，脚本会报错并指出冲突。

## 8. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `无法连接调试端口 9222` | Chrome 未带调试端口启动 | 重新执行 `node src/start_chrome.js` |
| `未找到打开 exam.yooc.me 的页面` | 考试页没开着，或用了别的调试端口 | 打开考试页；必要时 `--port 9223` |
| `页面尚未发起过 setting/get 请求` | 页面刚打开未加载完 | 在考试页按 F5 后重试 |
| 某题 `nomatch` | 答案文本与当前题面不一致 | 检查 `data/answers.json` 与最新题面，用 `build_answers.js` 重新汇总 |
| 某题 `fail` | 点击后选中态没出现 | 确认页面未被弹窗遮挡；刷新页面后重跑该题区间 |
| 抓手册报「未取到 PDF」 | OA 未登录，或直链的 `v` 与会话不匹配 | 用浏览器模式并先在调试 Chrome 登录 OA；或传入有效 Cookie |
| 抓手册报「附件未找到」 | 学校更新了附件名 | `node src/fetch_handbooks.js --list` 查看当前附件清单，必要时改 `src/fetch_handbooks.js` 里的 `TARGETS` |
| 中文乱码 | 终端编码 | Windows 下先执行 `chcp 65001` |

## 9. 安全与隐私

- 脚本只与考试平台域名、学校 OA 域名通信，token 由页面自身提供，**不落盘、不外传**；
- `data/paper.json`、`data/answers.json` 仅含本次试卷内容；`data/paper.json` 与运行产物已在 `.gitignore` 中排除，不会误提交；
- 抓手册时使用的 OA Cookie 只存在于命令参数与内存中，**不会被写入任何文件**；
- 调试 Chrome 使用独立用户目录，退出即销毁会话数据。
