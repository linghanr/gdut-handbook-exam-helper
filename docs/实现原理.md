# 实现原理

面向想改造本工具的开发者。内容基于对考试平台页面的实际逆向与调试记录。

---

## 1. 总体架构

```
Node 脚本（宿主机）
   │  CDP over WebSocket（ws://127.0.0.1:9222/devtools/page/<id>）
   ▼
Chrome 页面上下文（考试平台 SPA）
   │  页面内 fetch（带页面自身的 cookie/token）
   ▼
exambackend.yooc.me 试卷接口
```

所有对页面的操作都是「把一段 JS 表达式注入页面执行」：

- `src/lib/cdp.js` → `evaluate(wsUrl, expression)`：建立 WS、发送 `Runtime.evaluate`、取回 `result.value`；
- `src/exam_bot.js` 作为表达式注入，负责 DOM 交互；
- `src/run_exam.js` 在 Node 侧循环：取状态 → 注入机器人 → 读取结果。

---

## 2. 页面结构（关键选择器）

| 元素 | 选择器 | 说明 |
| --- | --- | --- |
| 题干 | `h3.jsx-3643416060` | 多选题节内编号是 **1..22**，**不是**全局题号 |
| 全局题号计数器 | `span.jsx-3527395752` | 文本形如 `42 / 100`，**以它为准** |
| 单选选项 | `li.jsx-2160564469.flex.items-center` | 文本在子元素 `div.flex-auto` |
| 多选选项 | `li.jsx-2550022912.flex.items-center` | 同上 |
| 选项文本 | `div.flex-auto` | 形如 `A.记过`（**字母+点+文本，无空格**） |
| 选中判定 | `li` 的 class 含 `_c` | 选中后追加，同时内部 `svg path` 的 `d` 换成对勾图标 |
| 下一题 | `BUTTON`，文本 `下一题` | |
| 交卷 | `BUTTON`，文本 `交卷` | **本工具从不点击** |

选项行**不是** `input`/`label`，而是 `li > div` + React `onClick`（页面上的 `input` 只有网易易盾验证码的隐藏框），因此只能「点」，不能「设 value」。

## 3. 数据来源与接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/exam/setting/get?examId=&userId=&token=&yibanId=` | 返回 `examuserId`、`submitType`、`isSubjectShuffle`、`isChoiceShuffle` 等 |
| `GET /api/exam/paper/get?examuserId=&token=&yibanId=` | 返回完整试卷（题面、选项、加密的 answer 字段） |
| `GET /api/exam/answer/get` | 读取服务端答案记录 |
| `POST /api/exam/submit/action` | 交卷（本工具不使用） |

`token` / `userId` / `yibanId` 无需手工配置：`src/fetch_paper.js` 在页面上下文读取 `performance.getEntriesByType('resource')`，从浏览器已发出的 `setting/get` 请求 URL 中直接复用。

### 试卷 JSON 结构

```jsonc
{
  "data": [
    { "sectionId": 1729955, "subjects": [ /* 78 道单选 */ ] },
    { "sectionId": 1729960, "subjects": [ /* 22 道多选 */ ] }
  ]
}
```

每道题：

```jsonc
{
  "subjectId": 88274512,
  "type": "choice",
  "points": "1",
  "inputs": "1",
  "title": ["题干文本"],
  "option": [["A 选项文本"], ["B 选项文本"], ["C 选项文本"], ["D 选项文本"]],
  "extra_img": [],
  "answer": "<密文>"
}
```

> `answer` 字段对全部 100 题都是同一个密文串，**并非逐题答案**，不能作为答案来源。

## 4. 答案存储

作答结果保存在浏览器 `localStorage`，服务端在交卷时才接收：

| 键 | 内容 |
| --- | --- |
| `examAnswersAtom` | `{"<examuserId>":{"<sectionIdx>-<subjectIdx>":"<值>"}}` |
| `examTakePosAtom` | `{"<examuserId>":{"sectionIdx":0,"subjectIdx":1,"sectionId":…,"subjectId":…}}` |
| `exam-paper-<examuserId>` | 试卷缓存 |

值的编码：

- 单选题 → 选项在**接口原始顺序**中的序号字符串，如 `"1"`；
- 多选题 → JSON 数组字符串，如 `"[1]"`、`"[0,1,2,3]"`。

因此 `verify_final.js` 需要把「页面显示顺序 → 接口原始顺序」做一次映射后再比对。

## 5. 两个致命坑（务必了解）

### 坑一：选项显示顺序 ≠ 接口顺序

平台开启了选项乱序（`isChoiceShuffle: 1`）。例如第 1 题接口顺序是
`[严重警告, 记过, 留校察看, 开除学籍]`，页面却显示为
`A.记过 B.留校察看 C.开除学籍 D.严重警告`。

**结论：作答必须按选项文本匹配，绝不能用数组下标。**

### 坑二：多选题的 `h3` 编号不是全局题号

多选题是独立 section，题目标题里的编号是该 section 内的 `1..22`；只有顶部的 `n / 100` 计数器是全局题号。
若误用 `h3` 编号判断"当前是第几题"，从第 79 题起会整体错位（表现为只翻到了最后一页却没有作答）。

### 坑三：回退要逐步点

「上一题」翻页是异步的，一次点击后需要等待计数器变化才能继续点；
实现上用 `goto(target)` 循环「点一次 → 等计数器变化 → 再判断」，而不是"连点 N 次"。

## 6. 答案推导方法（可复用）

1. 用 `src/find_in_handbook.js` 在两份手册纯文本中定位相关法规原文（输出带 PDF 页码）；
2. 引用 `data/handbook/法规导航索引.txt` 快速定位章节所在页；
3. 把原文条款与题目选项逐字比对，**注意数字型选项**（如 `60；30`）在原文里是分句表述，不能整串匹配；
4. 答案条目写成 `{q, answer, quote, src}`，`quote` 填原文句、`src` 填 `手册A pNNN` 形式；
5. 改完执行 `node src/build_answers.js` 重新汇总。

已验证的等效校验方式：把选中选项按分句拆开，逐一在手册全文中检索，
命中不了的选项多为「数字组合」「改写句」两类误报，需人工确认即可。

## 7. 安全边界

- 脚本只访问 `127.0.0.1:9222`（本地调试端口）与考试平台自身域名；
- `token` 由页面提供、不落盘；
- 除 `交卷` 按钮外不触发任何提交动作；
- `start_chrome.js` 使用独立用户目录 `~/.gdut-exam-chrome`，不影响日常浏览器。

### 7.1 交卷防护（三重保险）

平台的「交卷」按钮旁边就是「下一题」，且**在最后一题点「下一题」会弹出「确认交卷」对话框**——
自动点击「确定」就会直接交卷。因此机器人加了三层防护：

1. **点击拦截器**：注入时在 `document` 上注册捕获阶段监听器，作答期间把指向「交卷/提交」按钮的点击
   `preventDefault + stopPropagation` 掉（React 在根节点上派发，捕获阶段拦截可完全阻断）；
   作答结束自动解除，同学自己手动交卷不受影响（必要时可调 `window.__bot.releaseGuard()`）。
2. **最后一题保护**：`turn('next')` 在 `当前题号 >= 总题数` 时直接返回 `at-last`，不再点「下一题」。
3. **弹窗白名单**：只有在弹窗文本**不含** `交卷|提交|离开|退出|放弃|结束|重新|警告` 时才自动点「确定」，
   危险弹窗一律不点，而是记为异常交回给操作者。

> 实测教训：自动化脚本在最后一题点「下一题」触发「确认交卷」弹窗，
> 再由兜底逻辑点「确定」，就会在用户毫不知情的情况下完成交卷。防护三件套即为此而加。
